# Security and public deployment

The public snapshot excludes original environment files, Telegram sessions, private keys, database dumps, raw logs, videos and Git history. Do not publish the original backup or working directory. The content scanner is a bounded check, not an exhaustive credential-clearance claim.

Use new operator-owned credentials and restricted browser keys. Backend provider credentials belong on the server. The Google Maps browser key is intentionally used by the browser and should have HTTP-referrer/API restrictions and quotas; never substitute a server credential. The settings flow keeps session-entered keys in page memory. A deployment can explicitly set `GOOGLE_EARTH_ENABLED=true` and `GOOGLE_MAPS_BROWSER_KEY`; `/config` then intentionally delivers that public browser-restricted Maps key to clients. It never delivers the backend model, Telegram or administrative credentials.

Live collection, paid synthesis and video generation are separate explicit opt-ins. Administrative writes fail closed when the server key is absent. The shipped Compose ports bind to loopback. Keep the live profile there until public projection, provider rights and ingress limits have been reviewed. The local event and delivery APIs expose collected source text, and the narrated video endpoint performs full-file integrity checks before serving byte ranges. Public hosting requires separate treatment for allowed content, permitted AI processing and limits on requests, concurrent streams and WebSocket connections.

The database and one-shot initializer use `monitor_admin`; ordinary HTTP workers use the separate non-owning `monitor` role. Runtime receives only modeled-table DML, sequence USAGE/SELECT and migration-revision SELECT. It cannot create databases, roles, schemas, temporary tables or extensions, change the revision, assume the administrator or own application objects. Administrator environment variables are explicitly blanked in the HTTP service. Database access remains private to the Compose network. See [upgrade/rollback](docs/DB_UPGRADE.md) before changing an existing installation; rollback restores the older snapshot and its older permission properties.

The RC.3 candidate uses the Alpine reduced PostgreSQL/PostGIS profile, the pinned FlatGeobuf backport and Alpine's signed su-exec. Existing installations require a logical restore into the new volume and a measured compatibility check. The earlier Trixie profile has its own [RC.2 cutover and regression receipt](docs/qualification/2026-10-30-rc2-database-cutover-and-regressions.json). See [database upgrade and rollback](docs/DB_UPGRADE.md).

Backend UID 10001 and frontend UID 101 use dropped capabilities and no new privileges. Frontend and database root filesystems are read-only. The database entrypoint retains listed initialization capabilities. Its measured PostgreSQL PID 1 runs as UID 70 with zero effective capabilities and PROJ network access is disabled. The backend root is writable and its `/usr` SUID/SGID bits are removed. The RC.3 exact-image preflight exercised restricted runtime SQL, private database networking and seven HTTP header and cache cases. The [three-job hosted run on RC.2](docs/qualification/2026-10-30-rc2-hosted-qualified-source-ci.json) retains its own source and runtime identities. See [verification](docs/VERIFICATION.md).

Treat feed text and links as hostile input. Source text is data, never model instructions. Popup HTML is sanitized and external URLs require an allowed scheme. Structured model output and citation-ID membership are validated, while factual entailment remains unverified pending review.

Native feed collection has bounded concurrency, response bytes, deadlines, quotas and retry backoff. Original text, publication clocks, failures and revisions are retained; retrieval does not refresh an old source clock. Optional local inference is single-job, bounded and loopback-only. Narrated video accepts selected source IDs, creates local cards/audio and fully validates an MP4 before atomic publication. The qualified local AI/video path excludes Telegram material without the required source permission; inherited paid/model engines do not share that complete guard and remain disabled and unqualified.

The RC.2 backend replaces the general-purpose FFmpeg package stack with a SHA/signature-verified FFmpeg 9.0.2 source build containing only required local formats and `file`/`pipe` protocols. [Actual offline media qualification](docs/qualification/2026-10-30-backend-security-remediation.json) exercises speech, concatenation, complete decoding and rejection of HTTPS/HLS; the [separate real-source run](docs/qualification/2026-10-30-rc2-local-generation.json) passed 24 API/PostGIS/model/MP4 checks. This reduces network-parser exposure without claiming all retained local parsers safe. Original source archives, build configuration and dependency notices have separate distribution obligations.

The dated [OS security review](docs/OS_SECURITY_REVIEW.md) retains unresolved backend/database findings, vendor backport comparisons and frontend fixes. Python/npm advisory passes cover different inventories and do not clear OS packages, the Docker host, browser, GPU, builder stages or unknown vulnerabilities. [Dependency inventories](docs/qualification/software-inventory/README.md) distinguish all lockfile packages from the production dependency closure and bundled static assets. No blanket zero-vulnerability claim is made.

Record counts include aliases and are not unique-CVE or exploitability counts. Input restrictions and absent components are qualified exposure constraints, not blanket waivers. Later image changes require their own binding; earlier observations are not carried forward as tests of unmeasured bytes.

Caption/transcript text is bounded, checked against exact narration hashes and escaped before constructing local WebVTT; the video URL is built only from the configured API origin and validated content filename. Cancelled/replaced caption resources are revoked and cannot be reattached while fresh verification is pending. This is integrity/lifecycle checking, not semantic or factual verification. A native Firefox paused-repaint limit has explicit user-resume guidance and an exact transcript alternative; the application does not force playback, seek or create a new video to hide that limit. Public receipts use hashes, timing and bounded outcomes rather than raw publisher narration, VTT bodies or real-source screenshots.

Do not include keys, source raw logs or a database in a vulnerability report. Privately report the affected code, minimal synthetic reproduction and software version to the repository owner.
